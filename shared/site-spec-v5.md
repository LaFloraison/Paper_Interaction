# Paper_Interaction 站点规范 v5

> 取代 v4。v4 产物（`sites/perrault-2020-game-focused.html`、`sites/feng-2026-knowledge-hgnn.html`）保持原样不动，v5 只对未来构建生效。
>
> **v5 的三条动机**：① 讲解质量优先于篇幅纪律——字数是裁剪工具，不是讲清楚的手段；② 站点要装得下拓展卡与引用考据，v4 的 Part A–E 自由分层撑不住；③ 把生成流程从"手写单一 HTML 文档"改成"卡片数据 → 渲染器编译"，以提速并让管道类缺陷在结构上不可能发生。
>
> 用户定稿时间：2026-10-08。

## 1. 站点结构：7 章

论文的物理结构就是站点的物理结构。**图、表、公式、算法在其所属章节就地讲解**——读者拿着论文与站点对读时，位置一致。

| 章 | 名称 | 内容 | 典型卡数 |
|---|---|---|---|
| 1 | **Title** | 标题里每个核心概念一卡讲透；论文类型与发表场所（venue 意味着什么门槛） | 3–6 |
| 2 | **Pre-knowledge** | 读懂本文所需的**全部**前置概念（双卡制）+ **拓展小节**（家族谱系，§3.4） | 15–40+ |
| 3 | **Abstract** | 逐句读摘要：它主张什么、哪些主张带数字、这些数字在正文哪里兑现、哪些是空话 | 2–4 |
| 4 | **Introduction** | 问题是什么、缺口在哪、贡献清单逐条、作者如何推销、引言的图（若有） | 4–8 |
| 5 | **Method** | 每个编号公式一卡、每个方法图一卡、每个模块一卡、交互实验室 | 20–60+ |
| 6 | **Experiments** | 数据集与度量、每张表一卡、每张实验图一卡、消融、交互实验室 | 15–40+ |
| 7 | **Conclusion** | 论文自己的结论/局限/未来工作 + **批判节**（我们的审计账 + 未答问题） | 4–10 |
| — | **Wrap-up**（不编号） | 知识地图、数字索引、综合自测、下篇预告 | 2–4 |
| — | **References**（不编号，附录） | 三层引用制度（§3.5） | 3–15 |

**规则**
- 引用附录不编号——它不该与 Method 平起平坐。
- 章内分节，节即 group（如 `5.3 The rule ledger`）。导航按 章 → 节 → 卡 三级。
- 特殊论文可调整结构（如综述、理论论文），但必须在蓝图首页写明"为何偏离 7 章"。
- 第 2 章与拓展小节各带**跳过测验**（"我懂决策树 → 跳过本节"），供熟练读者快速通过。

## 2. 元规则：这个项目在做什么，以及先讲清楚、再拆卡

### 2.0 第一原则（用户 2026-10-08 定稿，一切规则由此推导）

> 几乎就是把原文拆开讲：**原文有的，卡片里都有；原文没讲清楚的，卡片里讲清楚；读者缺的知识、素养与经验，补足并训练。卡片只是一种形式，目的是减少读者长篇学习的认知负担。**

| # | 判据 | 可检查的表现 |
|---|---|---|
| 1 | **全量覆盖** | 论文每个论断 / 图表 / 公式都有落点；综合门交"覆盖账"（论文每节 → 卡片），对不上账 = 缺口 |
| 2 | **澄清** | 论文没讲清的（设计动机、符号来源、失效边界、数字是否正确）卡片必须讲清；**论文的沉默也是题目** |
| 3 | **补足与训练** | 缺失的前置知识 / 领域框架 / 科学素养 → 拓展小节补；补完必须练（习题） |
| 4 | **卡片是形式** | 卡片唯一职责 = 把长篇学习的认知负担切成能一次消化的单元。**切卡边界画在"注意力单元"处，不画在长度处，也不画在"知识点个数"处。** |

第 4 条是判据 1–3 的**服务者**，不是它们的限制器。任何"为了少几张卡"而牺牲覆盖、澄清或补足的写法，一律不合格。

### 2.1 两步法

1. **完整讲解稿**：为每个话题写一份不限长度的完整讲解，读者设定为"顶尖名校本科生 / 未来学者"——数学成熟、要求严谨、不接受手挥。存 `decomposition/{slug}/topics/{topic}.md`。
2. **拆卡**：把讲解稿**按自然接缝**拆成卡片。拆分依据是"一个自足的讲解单位"，不是长度。拆成几张由讲解的结构决定。

讲解稿是**审计物证**：综合门 B 用它判定"讲没讲清楚"，蓝图与卡片都必须能追溯到它。

### 2.2 四条硬判据（取代所有字数限制）

生成卡时逐条自检，审卡代理也按这四条判：

1. **完整性** — 读完能回答：**为什么需要它 / 它是什么 / 它怎么运作 / 它何时失效**。四问答不全 = 不完整。
2. **自足性** — 读者若从这张卡开始，也要能跟上：需要的结论就地重述，或显式回指（"卡 12 的结论：……"）。
3. **定义优先** — **未定义的术语不许出现**。每个术语首次使用处必须已有定义（正式定义 + 白话重述）。这是取代"每段新术语 ≤1"的真规则。
4. **清晰性** — 要三段加一个例子才讲得清，就给三段加一个例子。**篇幅服从清晰，而非相反。**

### 2.3 唯一保留的排版纪律

- **一张卡只承担一个自足的讲解单位**（"一个知识点"的粒度由讲解的自然结构定义，不由长度定义）。
- **一段只做一件事**——这是分段与切卡的依据，不是长度天花板。

## 3. 卡片解剖

### 3.1 通用骨架

```
[卡头] kicker（章 · 节 · 类型）+ 标题 + data-kp（仅 b 卡 / 知识点卡）+ ✚ 自定义插卡
[是什么]
[例子]
[习题]
[收尾] "本文如何用它"衔接 callout（知识点 b 卡 / 公式卡 / 展品卡）或 "下一卡"
```

三段用 phase 标签显式分段，顺序不可倒：

```html
<div class="phase ph-what"><span>WHAT</span></div>
<div class="phase ph-ex"><span>EXAMPLE</span></div>
<div class="phase ph-quiz"><span>EXERCISES</span></div>
```

### 3.2 「是什么」段 = 定义 → 动机 → 直觉 → 公式

v4 的"加粗白话定义句"被**双层定义盒**取代。定义盒固定出现在本段**最前**：

```
┌ Definition ─────────────────────────────────────────┐
│ 正式定义：<严谨表述，术语就地括注>                     │
│ 白话重述：<一句人话，零行话>                           │
└─────────────────────────────────────────────────────┘
```

其后依次：
1. **动机** — 为什么需要它；没有它会怎样。讲透为止，不限句数。
2. **直觉积木** — 逐个搭，每块用数值/表格/比喻落地。新术语在出现前必须先有定义。
3. **公式**（若有）— 本段**最后**出场；逐符号讲"它从哪个直觉来"；遮住公式后文字仍自足。

自检：读者能凭此段向别人复述"这是什么、为什么有它、怎么运作、什么时候不灵"。

### 3.3 「例子」「习题」两段

**例子** — ≥2 个由小到大的实例（第 1 个 ≤3 步能上手）：
- 每个数字**先用 Python 算过再写**（记入蓝图"已验证数值"）。
- 每步写出算术过程 + 为什么这么做，不只给结果。
- 关键前提就地重述，不靠"如前所述"。
- 例子合起来覆盖"是什么"的全部关键特征；覆盖不到的显式声明"本例未展示 X"。
- 图形卡 = 逐要素读图走查（每个轴、每个子图、每列都要走到，略过要声明）；实验室卡 = 分步任务。

**习题** — **题数不设上限，也不以 3 为配额：多少道由"读者要真正理解"决定。** 可检查的代理是**层次覆盖**——理解 / 应用 / 迁移三层每层至少一道（构建器强制），其余判据：

- 每个本卡点破过的常见误区，配一道专属题（否则针对性反馈无从触发）；
- 公式卡 / 数值卡：每种算术变体（符号方向、运算次序、边界情形）各一道；
- 唯一的"上限"是：不出重复考点的凑数题。

**卡片过大时，习题单独成卡**（`kind: "practice"`）：教学卡只留"是什么 + 例子"，习题迁到紧随其后的习题卡。习题卡的结构：**是什么 = 这组题练什么 + 需要提前握在手里的结论清单**（不引入新概念）→ **例子 = 一道完全讲解的样板题**（让读者知道每题长什么样）→ **习题 = 题目集合**。习题卡用 `for` 字段指回源卡，导航与大纲据此显示"Practice set for card 37"。判据：**当讲解 + 例子 + 习题三样都长时，先拆习题，再考虑拆讲解。**

其余习题纪律不变：
- 选择题**每个**错误选项带针对性解析，说中"选它的人怎么想的"。
- 数值题四件套 `answer / tol / hint / sol`；hint 指向错因而非答案；sol 展示完整算式。
- 应用题数字 ≠ 例子数字（防背答案）。

### 3.4 卡片类型（9 类）

1. **标题解码卡** — 标题里每个核心概念一卡。
2. **知识点双卡制** — 每个知识点两张：
   - **a · 一般理论卡**：该知识点在论文之外的一般形态。读者不读论文、没有先修基础，也应能从此卡真正学会。
   - **b · 在本文中卡**：论文如何实例化它；显式点破"这里特化了什么"；与一般形态的差异必须写清。`data-kp` 锚点放 b 卡。
   - 禁止把一般理论与文中用法挤在一卡。
3. **公式卡**（一卡一式）— 逐符号拆解 + 为什么需要它 + 推导还原 + 已验证数值实例。
4. **图形卡（一图一卡）· 表格卡（一表一卡）** — **原图 base64 内嵌**；逐要素走查；这张图在论证链里的角色。
5. **交互实验室卡** — 核心机制必配；分步任务带"为什么"。
6. **拓展卡（v5 新增）** — 见下。
7. **引用卡（v5 新增）** — 见 §3.5。
8. **习题卡（v5 新增）** — 见 §3.3：卡过大时把习题单独成卡，`for` 指回源卡。
9. **叙事 / 地图 / 批判 / 总结卡**。

#### 拓展卡（Extension）

**用途**：有些东西不影响读懂本文，但加上它们读者对这个领域才有完整的框架。**教学目标是科学素养与领域综合理解**，不是最低限度读懂。

**尺度：应有尽有，有备无患。默认开。**

- **唯一的不开理由**：与这篇论文及其所属领域**无关**。
- **"读者可能已经知道"不是理由。** 你不知道读者是否真有深刻理解，所以有备无患。**这条疑虑由跳过测验解决**——每个拓展小节自带跳过测验，懂的人自己跳；正因为能跳，"不确定读者会不会"就再也不能当作省略的借口。
- **本项目的失败模式是偷懒（该讲而没讲），不是臃肿（讲了但读者跳过了）。**

**选址判据**（用来决定挂在哪个章，不是用来决定开不开）：读懂**这篇**论文会在这里卡住吗？这篇论文的贡献是**相对谁**定义的？

**卡数不设上限。** 一个话题拆成 3 张还是 100 张都可以（如决策树家族：它是什么 → 有哪几类 → 每类长什么样、适用什么、什么时候失效 → 与本文所用的那一支的关系）。**要求只有一个：讲清楚。**

**呈现形式**：以**小节**为单位（`Extension: Decision trees`），由若干卡片组成，挂在相关章节内；若话题是跨章的家族谱系，可挂在章末或 Wrap-up 前。小节开头有一张"总览卡"（这个话题是什么、为什么值得看、本节包含哪些卡），结尾有跳过测验。

**纪律**：拓展卡同样受 §2.2 四条硬判据约束；不许因为"这是拓展"就降低严谨度。

#### 拓展库（写一次，各站编译内嵌）

通用性强的拓展小节（图论基础、深度学习基础、决策树家族、论文阅读元技能……）是**项目级资产**，存放在 `shared/kp-library/{kp-id}/`，写一次即可。任何用到它的论文，构建时由渲染器**直接编译进该站点**（站点仍自包含）。只有本论文特有的实例化才新写。

这条决定了工作量结构：**拓展库的成本付一次，收益覆盖所有后续论文。**

### 3.5 引用制度（三层）

目标：读完后对这篇论文的**来龙去脉**有清晰掌握。

| 层 | 位置 | 形式 |
|---|---|---|
| **① 就地注** | 正文引用点（该章内） | 1–2 句：**它是谁**（作者/年/一句话身份）+ **这里为什么引它**（提供定义？最近的对手？数据集来源？）。不是卡，是 callout。 |
| **② 承重引用卡** | 引用附录 | 约 5–10 篇：问题的定义者、最近的竞争对手、数据集/基线/关键组件来源、本文直接改进的对象。每篇一张卡（三段式）：它做了什么 → 本文为什么必须引它 → 本文从它那里拿了什么、改了什么。 |
| **③ 引用总表** | 引用附录 | 其余全部引用一行一篇：谁 / 年 / 在这篇论文里扮演什么角色（dataset / baseline / component / related work / motivation）。**逐条读完即可，不开卡。** |

另配一张**谱系图**：来龙（谁定义了问题）→ 本文（改了什么）→ 去脉（谁在其后延伸）。图由 KaTeX/HTML 绘制，不用外链。

## 4. 语言：英文单语

- 站点正文、界面文案、习题、动态 JS 文案**全部英文**。
- **不再有中英文本块对**、不再有语言切换按钮、不再有 `.lz/.len`、不再有 `applyLang`/`toggleLang`/`data-title-zh`。
- 项目**内部文档**（蓝图、讲解稿 topics/、审卡记录、登记表）用中文——它们是给用户看的，不是站点内容。
- 术语第一次出现时给英文定义；确需给出中文对照时，写在括号里（如 "a hyperedge (超边)——"），但**不作为第二语言版本重复全段**。

## 5. 三重质量门

任何一批卡片，三道门全过才算完成。

### 5.1 数值门（生成者自检，先于读者门）

- 卡内**每一个**数字（正文算例 + 习题题干 + answer + tol）用 Python 实际算过。
- 蓝图"已验证数值"节逐条记录：卡号 / 输入 / 算式 / 输出。
- **边写边算禁止**——先算完一张卡的全部数字，再动笔写这张卡。

### 5.2 读者门（并行审卡代理）

**读者模型（v5 更新）**：
> 顶尖名校本科生 / 未来学者。数学成熟，严肃、严谨，有求知欲。**但没有读过这篇论文，可能也没学过这个话题本身，也不了解该子领域的历史。**

不需要哄，不需要"通俗化到失真的比喻"；需要的是**准确、完整、有定义、有例子、有边界**。

**流程（并行）**：
1. 一章的卡片写完后，一次性并发派出 N 个代理（**一卡一个**，单条消息同时发，并发上限 ~10）。
2. 每个代理**只给该卡的渲染后内容**（剥掉 base64 图片，保留公式源码），不给论文、不给蓝图、不给其他卡。
3. 收齐 verdict → 并行修 → **只复审 FAIL 的卡**。
4. 一卡一代理是铁律：多卡合并会让代理带上上下文，"未读过本文"就假了。

评分标准用 `shared/card-quality-rubric.md` 原文。

### 5.3 综合门（全站，两个代理）

读者门是**盲的**（一卡一代理），抓不到跨卡矛盾，也判不了"整站是否讲透了来龙去脉"。综合门补这个洞，全站卡片通过读者门后跑：

**A · 全局一致性审**
- 输入：全站卡片摘要表（卡号 / 标题 / 定义句 / 公式 / 全部习题题干与答案）+ 已验证数值总账 + 论文原表数字。
- 检查：跨卡数字矛盾、同一术语两种译法/两种含义、某卡习题答案与另一卡例子冲突、卡片与论文原表不符、重复讲解（同一概念在两处从零讲起）。
- 输出：矛盾清单（卡号对 + 引原句 + 改法）。

**B · 领域考官审（来龙去脉 + 综合理解）**
- 输入：论文原文 + 全站大纲（章节结构 + 卡标题 + 每卡定义句）——**不给卡片正文**，以便判"覆盖"而非"文笔"。
- 必须回答四问：
  1. **谱系**：这篇论文从谁而来（3–5 篇直接前身）、改了什么、谁在它之后？
  2. **从业者决策**：这个子领域里做事的人要在哪些点上做选择？本文各如何选？替代方案与代价是什么？
  3. **残留无知**：读完全站，我仍然不知道什么？
  4. **裁决**：若我是这个方向的新博士生，这站是否足以让我 (a) 复述论文 (b) 向别人解释它为何重要 (c) 在组会上有理有据地质疑它？
- 输出：**缺口清单** → 逐条转成新卡（拓展卡或引用卡）。

评分标准见 `shared/synthesis-rubric.md`。

**（可选）C · 复现者审**：能否仅凭本站把方法实现出来（超参、形状、预处理、评测协议是否齐备）。

### 6.2 卡片数据格式

```json
{
  "id": 42,
  "chapter": "method",
  "section": "5.4 Rule-content encoding",
  "kind": "formula",
  "kp": "kp-gbdt",
  "title": "Equation (6): rule position weight",
  "skip": false,
  "what":  [ {"t":"definition","formal":"...","plain":"..."},
             {"t":"p","md":"..."},
             {"t":"steps","items":[{"md":"...","why":"..."}]},
             {"t":"formula","tex":"\\mu_p = ...","gloss":[{"sym":"\\alpha","md":"..."}]},
             {"t":"callout","md":"..."} ],
  "example":[ {"t":"calc","md":"..."}, {"t":"figure","src":"figures/fig2.png","alt":"..."} ],
  "quiz":  [ {"t":"choice","q":"...","opts":[{"md":"...","correct":true,"expl":"..."}]},
             {"t":"num","q":"...","answer":0.6,"tol":0.01,"hint":"...","sol":"...","expl":"..."} ],
  "close": {"t":"callout","md":"How this paper uses it: ..."}
}
```

块词汇表是**封闭**的：`definition / p / steps / formula / callout / figure / table / calc / list / quote`（`what`、`example` 共用）。渲染器对每种块有唯一正确输出。

**因此以下缺陷在结构上不可能发生**：属性引号破损、拼接乱序、三段式缺段/乱序、quiz 四件套缺失、业务区出现反引号、占位符残留、`.lz/.len` 漏删。

### 6.3 构建与校验命令

```
python tools/new_paper.py {slug}
python tools/extract_figures.py content/{slug}/figures/clips.json
python tools/build_site.py {slug}          # → sites/{slug}.html
python tools/validate.py sites/{slug}.html # 数据层 + 渲染层双重校验
python tools/embed_katex.py sites/{slug}.html
python tools/upd_index.py                  # 大厅 + 知识点目录
```

## 8. 全局知识地图

大厅 `index.html` 的核心不是论文列表，而是一张**跨论文的知识地图**——每拆完一篇，它就生长一格。

- **节点** = 知识点（`kp-xxx`）。**边** = 四类关系：
  - **前置**（A 是 B 的前提）→ 实线箭头
  - **相关**（同族、常一起出现）→ 虚线
  - **对比**（互为替代/竞争者）→ 双向线
  - **被取代**（更深版本覆盖旧卡）→ 灰色虚线
- **归组**：按领域/族聚类（图学习 / 树模型 / 评测协议 …），同组相邻。
- **交互**：点节点 → 跳 `sites/{slug}.html#kp-xxx`；悬停 → 一句话摘要 + 出处论文。
- **未覆盖节点**：某篇论文引用了、但还没有站点讲过的知识点，灰色显示 `not yet covered`。这张图同时是**下一篇论文该先补什么**的待办清单。
- **数据源**：`shared/knowledge-map.json`（nodes + edges + groups），与登记表同步维护；`tools/upd_index.py` 渲染进大厅。
- **实现约束**：零 CDN → 手写 SVG + 原生 JS；**布局必须确定性**（坐标或聚类结果固定，每次加载不变——会重排的知识地图会让人失去方位感）；不做力导向动画。
