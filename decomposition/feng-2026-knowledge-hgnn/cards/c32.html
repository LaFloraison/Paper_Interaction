式 (8)：把每棵树的得分列拼成一条账Eq. (8): binding the per-tree columns into one ledger

是什么WHAT

上一卡算出了每棵树自己的一列得分。树队有 K 棵，就有 K 列。式 (8) 的动作最朴素不过：按树号顺序，把 K 列依次接起来，成为一条长向量 Xr——这是每个顶点最终的"规则知识账"。

The last card produced one score column per tree; a K-tree team yields K columns. Eq. (8)'s move is the plainest: in tree order, join the K columns end to end into one long vector Xr — each vertex's final "rule-knowledge ledger".

拼接口诀：位数 = 各树提问点个数之和；顺序 = 第 1 棵树的整列、接第 2 棵树的整列……；每个顶点各有一条自己的长账（长度相同、内容各异）。

Concatenation in one line: length = sum of all trees' question counts; order = tree 1's whole column, then tree 2's …; every vertex owns one such long ledger (same length, different contents).

逐符号：φr1…φrK = 上一卡每棵树的得分列；符号 ‖ 读作"拼接"——把两列首尾相接、不加减不混合，像把两张答题卡订成一页；K = 树队里树的棵数；xv = 顶点 v 的特征串；下标 [v] 表示"这条账归 v"。整式一句话：K 列首尾相接 = 一条长账。Symbol by symbol: φr1…φrK = the per-tree columns from the last card; the symbol ‖ reads "concatenate" — join two columns end to end, no adding, no blending, like binding two answer sheets into one; K = the number of trees; xv = vertex v's features; the subscript [v] says "this ledger belongs to v". The whole line in a breath: K columns end to end = one long ledger.

常见误解：Common misconception: 拼接不是相加，也不是取平均——位数会变多（相加会变少、平均会不变），各列原封不动保留。所以 Xr 的长度随树队规模增长：更多树 = 更长的账，而不是被揉成一个数。 Concatenation is neither addition nor averaging — the length grows (addition would shrink it, averaging keeps it), and each column stays intact. So Xr's length grows with the team: more trees = a longer ledger, never squashed into one number.
例子EXAMPLE

例 1（顶点甲拼账，跟着接）：上一卡算好的两列：T₁ = [0, 0]（2 位）、T₂ = [1.125, 1.0, 0]（3 位）。按树号首尾相接：Xr = [0, 0, 1.125, 1.0, 0]——共 2 + 3 = 5 位。读账：第 1、2 格是 T₁ 的两个问题（都被解释，0）；第 3、4、5 格是 T₂ 的三个问题（前两条悬账，根上那条 1.125 最重）。每一格都能指名道姓地回溯到"哪棵树的哪个提问点"——账本的每一笔都查得到出处。

Example 1 (bind A's ledger, follow along): the two columns from the last card: T₁ = [0, 0] (2 slots), T₂ = [1.125, 1.0, 0] (3 slots). In tree order, end to end: Xr = [0, 0, 1.125, 1.0, 0] — 2 + 3 = 5 slots. Reading: slots 1–2 are T₁'s questions (both explained, 0); slots 3–5 are T₂'s (two unsettled, the root one at 1.125 heaviest). Every slot traces back to "which tree's which question" — each entry auditable.

例 2（顶点乙的账并排看）：上一卡算好：T₁ = [1.125, 0]、T₂ = [0, 0, 0] → Xr = [1.125, 0, 0, 0, 0]。两本账摆一起：甲 [0, 0, 1.125, 1.0, 0]、乙 [1.125, 0, 0, 0, 0]——同样的 5 格，一个"在 T₂ 上留了根级悬账"，一个"在 T₁ 上留了根级悬账"。账本按人开页、每页 5 格；不同人、不同笔迹。

Example 2 (B's ledger side by side): from the last card: T₁ = [1.125, 0], T₂ = [0, 0, 0] → Xr = [1.125, 0, 0, 0, 0]. Two ledgers together: A [0, 0, 1.125, 1.0, 0], B [1.125, 0, 0, 0, 0] — same 5 slots; one leaves a root-level entry under T₂, the other under T₁. One page per person, 5 slots each; different people, different handwriting.
