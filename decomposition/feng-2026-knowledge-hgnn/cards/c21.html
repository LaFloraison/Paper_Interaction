Method · the framework方法篇 · 框架总览

全论文只有一个配方：先备料，再加工The whole paper, one recipe: prep first, then process

是什么WHAT

老方法的流程是：把每本书的原始标签直接丢进抹平机，顺着读书会平均、分类。论文说：不行，机器会抹掉太多东西——何不在进机器之前，先给每本书备两份料？

The old pipeline: throw each book's raw label straight into the smoothing machine, average along clubs, classify. The paper says no — the machine erases too much. Why not prep two sheets of ingredients per book before it enters the machine?

论文的配方只有两步：第一步“备料”——把要用到的每种数据各自加工成一小串数字（这份数字就叫知识向量）；第二步“加工”——把几串数字合成一份，交给那台打分机器，让它顺着超图关系分类。

The paper's recipe has just two steps: step 1 "prep" — each kind of data gets processed on its own into a short string of numbers (that string is called a knowledge vector); step 2 "process" — the strings merge into one, which the scoring machine uses to classify along the hypergraph.

配方里的两样东西值得多说一句：备料的机器按"有几种数据"配置——喂几路数据，就放几台（论文叫它 encoder，编码器："把原始资料翻译成数字的机器"）；加工那一步内部又劈成两小段：先把几串数字合成一份（论文叫 fusion，融合："把几份成绩单订成一份"），再进打分机器打分。合成发生在第二步内部，不是独立的第三步。

Two things in the recipe deserve a sentence each: the prep machines number one per data source — feed n data streams, install n machines (the paper calls them encoders: "translators from raw material into numbers"); and the processing step itself splits in two halves: first the strings merge into one (the paper calls it fusion: "stapling several report cards into one"), then the scoring machine runs. The merge happens inside step 2 — not as a separate third step.

公式仅供对照，不必计算。逐符号对照白话：Di = 第 i 种数据（一堆原始资料）；φi = 对应的备料机器（把 Di 翻译成数字）；Ki = 翻译出的那串数字（成绩单）；ψ = 订成绩单的那步（融合）；H = 超图的结构表（谁和谁同组）；HGNN(·,H) = 打分机器（顺着超图反复平均后分类）；Y = 最终分类结果。The equation is for reference only — no need to compute. Symbol by plain word: Di = the i-th data source (raw material); φi = its prep machine (translating Di into numbers); Ki = the resulting string (a report card); ψ = the stapling step (fusion); H = the hypergraph's structure table (who groups with whom); HGNN(·, H) = the scoring machine (averages along the hypergraph, then classifies); Y = the final classification.

老配方和新配方的差别：老方法的打分机器前面只有"一层自己学出来的可调参数"（论文记作 Θ，一个希腊字母而已——第 22 卡会正式见到它），没有备料这一步。论文把备料显式地插到了机器前面——机器没换，料换了。

Old recipe vs new: the old scoring machine had only "one layer of its own trainable knobs" in front (the paper writes it Θ — just a Greek letter; met properly at card 22), with no prep step. The paper inserts prep explicitly before the machine — same machine, better ingredients.

常见误解：Common misconception: 别以为论文发明了一台新机器——第二步的打分机器就是经典 HGNN（2019 年的老成果），论文没动它。全部新意都在"备料"这一步，以及料怎么接进机器。 Do not think the paper invented a new machine — step 2's scorer is the classic HGNN (a 2019 result) left untouched. Every bit of novelty lives in the "prep" step and how its output plugs into the machine.
例子EXAMPLE

例 1（图书馆故事，卡内自足版）：设定：一家图书馆要按主题给书分类；书有原始标签（特征），书还被编进各种读书会（结构）。第一步：会计数"这本书参加几个读书会" → 一串数字（一列人脉账）；老学究按借阅档案查"这本书踩中了哪几条规律" → 另一串数字（一列规则账）。第二步：把两列数字订成一份，塞进抹平机，机器顺着读书会关系给每本书打分分类。

Example 1 (the library story, self-contained): setup: a library classifies books by topic; books have raw labels (features) and belong to reading clubs (structure). Step 1: the accountant counts "how many clubs does this book join" → a string of numbers (the membership ledger); the scholar checks the borrowing archive for "which rules does this book trigger" → another string (the rule ledger). Step 2: the two ledgers are stapled into one and handed to the smoothing machine, which scores and classifies each book along the club relations.

例 2（论文喂了几路料——数字走查）：论文实际只用两种数据：① 每本书的原始标签（论文符号 X）→ 一台备料机器（代号 TDR-Encoder，第 27 卡专讲）；② 读书会的编组表（论文符号 H）→ 另一台（代号 HOI-Encoder，第 24 卡专讲）。所以：2 路数据 → 2 台机器 → 2 串数字 → 合成 1 份 → 1 个分类结果。两个成品型号由此分家：只吃"规则账"的叫 RD-HGNN，两本账都吃的叫 DD-HGNN（第 34 卡给公式）。

Example 2 (how much data the paper feeds — a numeric walkthrough): the paper uses exactly two sources: (1) each book's raw labels (paper's symbol X) → one prep machine (codenamed TDR-Encoder, card 27); (2) the club rosters (paper's symbol H) → another (codenamed HOI-Encoder, card 24). So: 2 streams → 2 machines → 2 strings → merged into 1 → 1 classification. The two final models split from here: rule ledger only is RD-HGNN; both ledgers is DD-HGNN (equations at card 34).
