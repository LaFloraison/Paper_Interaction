HOI-Encoder：把"人脉"存档HOI-Encoder: archiving your memberships

是什么WHAT

叙事场的会计登场。她的工作只有一件：对每个顶点，数清它被几条超边圈住，报出一个数。这个"数人脉"的小机器，论文叫它 HOI-Encoder（高阶关联编码器——"关联"就是"谁在哪个组里"这层关系）。

The story's accountant takes the stage. Her single job: for each vertex, count how many hyperedges embrace it, report one number. This little membership-counting machine is the paper's HOI-Encoder ("incidence" = the who-belongs-to-which-group relation).

HOI-Encoder 做两件事：① 数出每个顶点参加了几条超边（一个整数）；② 把这个整数过一个小函数压成 0–1 之间的一个数，作为它的"结构显著性"存档。它不碰顶点自己的特征，只读超图的编组表——这一点很重要，后面会看到它为什么是"抗抹平"的关键。

The HOI-Encoder does two things: (1) count how many hyperedges each vertex joins (an integer); (2) squash that integer through a small function into a number between 0 and 1 — the vertex's archived "structural salience". It never touches the vertex's own features, reading only the roster table — remember this; it is why the archive survives smoothing.

那个"小函数"在本卡就叫 ρ（念"rho"）：本文取最简的一层——ρ(x) = σ(w·x + b)，其中 w、b 是两个可调的旋钮（论文最后取了 w=2、b=0），σ 是"把任意数压到 0 与 1 之间"的函数（第 4 卡的辣度打分器同源）。公式只是翻译，例 1 会把每个数替你算出来。

That small function is written ρ ("rho") in this card: the paper's simplest one-layer choice, ρ(x) = σ(w·x + b), where w and b are two tunable knobs (the paper settles on w = 2, b = 0) and σ is the "squash any number into 0-to-1" function (same family as card 4's spice scorer). The formula is just translation; Example 1 computes every number for you.

论文特意把存档设计成一个数（输出维度 Cs = 1）："人脉多要紧"这个问题一个数就答完了；而且单个数方便后面按位广播进规则账（第 33 卡）。

The paper deliberately archives a single number (output dimension Cs = 1): "how pivotal" is answered by one number, and a lone number broadcasts easily into the rule ledger slot-by-slot (card 33).

常见误解：Common misconception: "高阶"不等于"更复杂地重算特征"——HOI 的高阶指它数的是群体关系（一条超边圈住任意多个点），而它读的全是编组表里的 0/1，与特征无关。 "High-order" does not mean "recomputing features more intricately" — it means the HOI counts group relations (one hyperedge embraces any number of vertices), reading only 0/1s in the roster table, features untouched.
例子EXAMPLE

例 1（4 顶点小超图，跟着算）：沿用第 8/15 卡的编组表：v1 参加 1 个组、v2 参加 2 个、v3 参加 2 个、v4 参加 1 个。第一步数数：得到 1、2、2、1。第二步压一压：ρ(x) = σ(2x)，而 σ 的算法是 σ(x) = 1 ÷ (1 + e−x)（e ≈ 2.718，计算器上有这个键）。逐个算：v1 → σ(2) = 1 ÷ (1 + e−2) = 1 ÷ (1 + 0.1353) ≈ 0.8808；v2 → σ(4) = 1 ÷ (1 + e−4) ≈ 0.9820（v3 同）；v4 → 0.8808。存档 = [0.8808, 0.9820, 0.9820, 0.8808]——人脉王的 v2、v3 拿到最大显著性。

Example 1 (4-vertex toy, compute along): reuse cards 8/15's roster: v1 joins 1 group, v2 joins 2, v3 joins 2, v4 joins 1. Step one, count: 1, 2, 2, 1. Step two, squash: ρ(x) = σ(2x) with σ(x) = 1 ÷ (1 + e−x) (e ≈ 2.718, a calculator key). Compute: v1 → σ(2) = 1 ÷ (1 + 0.1353) ≈ 0.8808; v2 → σ(4) ≈ 0.9820 (v3 same); v4 → 0.8808. Archive = [0.8808, 0.9820, 0.9820, 0.8808] — the membership kings v2, v3 earn top salience.

例 2（加一条超边，账本立刻更新）：给这张超图添第 4 个组 e4 = {v1, v2, v3}（第 9 卡沙盒的勾选框场景）：参加数变成 v1: 2、v2: 3、v3: 3、v4: 1。存档随之变 [σ(4), σ(6), σ(6), σ(2)] ≈ [0.9820, 0.9975, 0.9975, 0.8808]——v2 由 0.9820 升到 0.9975。结构一动，账本即时重算。

Example 2 (add one hyperedge, the ledger updates): add a 4th group e4 = {v1, v2, v3} to the toy (card 9's checkbox scenario): counts become v1: 2, v2: 3, v3: 3, v4: 1. The archive follows: [σ(4), σ(6), σ(6), σ(2)] ≈ [0.9820, 0.9975, 0.9975, 0.8808] — v2 rises 0.9820 → 0.9975. Structure moves, the ledger recomputes instantly.
