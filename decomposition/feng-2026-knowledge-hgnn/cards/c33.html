Equation 9 · fusing the two ledgers公式 9 · 两本账合订

式 (9)：两本账怎么合订成一份特征Eq. (9): binding two ledgers into one feature set

是什么WHAT

现在右手边有两本账：结构账 Xs（每个顶点 1 个数——参加几条超边，第 25 卡）与规则账 Xr（每个顶点 5 个数——内容×位置的清单，第 32 卡）。要把它们合订成一份特征 Z，塞进打分机器。

Two ledgers now sit on the desk: the structural ledger Xs (one number per vertex — membership counts, card 25) and the rule ledger Xr (five numbers per vertex — the content×position lists, card 32). They must bind into one feature set Z for the scoring machine.

直接拼不行吗？论文说不行，并给了理由：两本账"厚度"悬殊（1 格 vs 5 格），直接拼成一页 6 格，那 1 格结构信息会被 5 格规则信息稀释——薄的那本等于没带。

Why not simply concatenate? The paper says no, with a reason: the ledgers differ wildly in "thickness" (1 slot vs 5). Pasted directly into a 6-slot page, the single structural slot gets diluted by five rule slots — the thin ledger might as well be left home.

合订配方两步：① 让结构账那个数"按位乘"进规则账的每一格（⊙，逐位相乘），得到一份"结构加权版"的规则账 X̃r；② 把加权版与原版并排拼成一页（‖），得到 10 格的 Z。

The binding recipe, two steps: (1) let the structural number multiply into every slot of the rule ledger (⊙, slot-wise), giving a "structure-weighted" copy X̃r; (2) staple the weighted copy and the original side by side (‖) into a 10-slot Z.

逐符号：Xs = 结构账（每人 1 个数）；Xr = 规则账（每人 5 个数）；⊙ = "逐位相乘"（一个数乘进一整列，每个格子都乘一遍）；X̃r = 加权后的规则账；‖ = "并排拼接"（第 32 卡的老朋友）；Z = 最终的"知识嵌入特征"（每人 5 + 5 = 10 个数）。读法：结构大的顶点，规则账被整体放大；结构小的顶点，规则账被整体压低。Symbol by symbol: Xs = structural ledger (1 number each); Xr = rule ledger (5 each); ⊙ = "slot-wise multiply" (one number times a whole column, every slot); X̃r = the weighted copy; ‖ = "side-by-side concatenation" (card 32's friend); Z = the final "knowledge-embedded feature" (5 + 5 = 10 numbers each). Reading: structurally rich vertices get their rule ledger amplified; structurally poor ones get it damped.

论文自己打了个比方：这像 Transformer 里的"位置编码"——把一个额外的信息（结构分量）注入进每位特征里，而不是在名单末尾另起一格。结果就是：真正要紧的顶点，它的规则账会被顶出来；边缘顶点被压低但不消失。

The paper's own analogy: this resembles positional encoding in Transformers — extra information (the structural weight) is injected into every slot rather than bolted on the end. Consequence: pivotal vertices' rule ledgers get pushed forward; marginal ones are damped but never deleted.

例子EXAMPLE

例 1（顶点甲合订，逐格算）：结构账 Xs(甲) = σ(2) ≈ 0.8808（他参加 2 个组，第 25 卡的算例）；规则账 Xr(甲) = [0, 0, 1.125, 1.0, 0]（第 32 卡算例）。逐位相乘：0.8808 × 0 = 0；0.8808 × 0 = 0；0.8808 × 1.125 ≈ 0.9909；0.8808 × 1.0 = 0.8808；0.8808 × 0 = 0。得 X̃r = [0, 0, 0.9909, 0.8808, 0]。

Example 1 (bind A's ledgers, slot by slot): structural Xs(A) = σ(2) ≈ 0.8808 (he joins 2 groups — card 25's walkthrough); rule Xr(A) = [0, 0, 1.125, 1.0, 0] (card 32's walkthrough). Slot-wise: 0.8808 × 0 = 0; × 0 = 0; 0.8808 × 1.125 ≈ 0.9909; 0.8808 × 1.0 = 0.8808; × 0 = 0. So X̃r = [0, 0, 0.9909, 0.8808, 0].

例 1 续（拼成 Z）：加权版 ‖ 原版 = [0, 0, 0.9909, 0.8808, 0] ‖ [0, 0, 1.125, 1.0, 0] → Z(甲) = [0, 0, 0.9909, 0.8808, 0, 0, 0, 1.125, 1.0, 0]，共 10 格。前 5 格是"被结构放大镜看过一遍"的规则账，后 5 格是原账——机器同时看到两种视角。

Example 1, continued (bind into Z): weighted ‖ original = [0, 0, 0.9909, 0.8808, 0] ‖ [0, 0, 1.125, 1.0, 0] → Z(A) = [0, 0, 0.9909, 0.8808, 0, 0, 0, 1.125, 1.0, 0], ten slots. The first five are the rule ledger seen through the structural magnifier; the last five are the original — the machine sees both views at once.

例 2（边缘顶点被压低）：若某顶点的结构账只有 Xs = 0.5（孤立，谁也不参加），规则账 [1.125, 0, 0, 0, 0] → 逐位乘：0.5 × 1.125 = 0.5625，其余仍 0 → X̃r = [0.5625, 0, 0, 0, 0]；Z = [0.5625, 0, 0, 0, 0, 1.125, 0, 0, 0, 0]。对比甲：结构分量 0.8808 对上 0.5，同一笔悬账 1.125 被压到 0.5625——结构的轻重，直接写进了规则账的每一格。

Example 2 (a marginal vertex, damped): suppose a vertex's structural ledger reads Xs = 0.5 (isolated, no groups) and its rule ledger [1.125, 0, 0, 0, 0] → slot-wise: 0.5 × 1.125 = 0.5625, rest stay 0 → X̃r = [0.5625, 0, 0, 0, 0]; Z = [0.5625, 0, 0, 0, 0, 1.125, 0, 0, 0, 0]. Against A's 0.8808, the same 1.125 entry is damped to 0.5625 — structural weight, written into every slot of the rule ledger.
