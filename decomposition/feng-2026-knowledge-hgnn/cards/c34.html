式 (10)：一台机器，两种装料法Eq. (10): one machine, two loading plans

是什么WHAT

备料车间全部完工：规则账 Xr（5 格）与融合账 Z（10 格）都造好了；打分机器（HGNN，第 22 卡）和超图结构 H 一直没变。剩下的只是装料选择——喂哪一本给机器。

The prep floor is finished: rule ledger Xr (5 slots) and fused ledger Z (10 slots) both built; the scoring machine (HGNN, card 22) and the hypergraph H never changed. All that remains is the loading choice — which ledger feeds the machine.

两种装料 = 两个型号：只喂规则账的叫 RD-HGNN（Rule-Driven，规则驱动）；喂融合账 Z（规则 + 结构）的叫 DD-HGNN（Dual-Driven，双驱）。它们是同一台机器、同一个骨架，唯一起差别的是料。

Two loading plans = two models: feeding only the rule ledger gives RD-HGNN (Rule-Driven); feeding the fused Z (rules + structure) gives DD-HGNN (Dual-Driven). Same machine, same skeleton — only the ingredient differs.

逐符号：φr(X, T) = 规则账的制造函数（树队 T 加上顶点特征 X → 账 Xr，第 32 卡）；φs(X) = 结构账的制造函数（编组表 → 账 Xs，论文里写作 φs(H)，此处简记）；ψ = 融合函数（MDK-Fusion，第 33 卡）；HGNN(·, H) = 打分机器顺着超图运转；两行唯一的差别：DD 的料多经过一次 ψ 融合。一句话：RD 喂 5 格料，DD 喂 10 格料，机器同款。Symbol by symbol: φr(X, T) = the rule-ledger maker (tree team T + features X → ledger Xr, card 32); φs(X) = the structural-ledger maker (roster → ledger Xs; the paper writes φs(H)); ψ = the fusion function (MDK-Fusion, card 33); HGNN(·, H) = the scoring machine running along the hypergraph; the only difference between the lines: DD's ingredient passes through ψ once more. One breath: RD eats 5 slots, DD eats 10, same machine.

例子EXAMPLE

例 1（顶点甲走两个型号）：RD-HGNN 的输入 = Xr(甲) = [0, 0, 1.125, 1.0, 0]（5 格）；DD-HGNN 的输入 = Z(甲) = [0, 0, 0.9909, 0.8808, 0, 0, 0, 1.125, 1.0, 0]（10 格，第 33 卡算例）。之后两台"机器"做的事完全一样：沿超图收集—平均—归一化，最后输出分类。所以比较两者成绩时，变量只有一个：料里"有没有结构的声音"。

Example 1 (vertex A through both models): RD-HGNN's input = Xr(A) = [0, 0, 1.125, 1.0, 0] (5 slots); DD-HGNN's input = Z(A) = [0, 0, 0.9909, 0.8808, 0, 0, 0, 1.125, 1.0, 0] (10 slots, card 33's walkthrough). From there the two "machines" do exactly the same: collect–average–normalize along the hypergraph, then classify. So comparing their scores varies exactly one thing: whether the ingredient carries the structural voice.

例 2（论文实测的选型规律——Table V 真实数字）：看"DD 减 RD"在十数据集上的符号：图数据集上全是负的——Cora 上 RD 88.64、DD 87.22（DD 反而低 1.42）、Github、Amazon-P、Amazon-C 同样 RD 略胜；超图数据集上全是正的——CA-Cora 上 DD 79.75、RD 79.36（DD 高 0.39）、CC-Cora 上 DD 更是高出 1.76。规律一句话：结构越复杂（超边的世界），双驱越占便宜；关系越简单（两两边就够），单驱反而更利落。

Example 2 (the paper's selection pattern — real Table V numbers): watch the sign of "DD − RD" across the ten datasets: negative on every graph dataset — on Cora, RD 88.64 vs DD 87.22 (DD lower by 1.42), with Github, Amazon-P, Amazon-C likewise slightly favoring RD; positive on every hypergraph dataset — CA-Cora: DD 79.75 vs RD 79.36 (DD higher by 0.39), CC-Cora's gap reaching 1.76. One line: the richer the structure (hyperedges), the more the dual-drive pays; the simpler the relations (pairwise suffices), the leaner single-drive wins.
