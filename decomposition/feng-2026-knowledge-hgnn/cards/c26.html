证明：换一个登记顺序，账本一字不变Proof: re-register in any order, the ledger stands identical

是什么WHAT

上一卡的会计有一个隐忧：编组表里，哪条超边算"第 1 列"纯看你怎么登记——如果换一种登记顺序，账本跟着变，那模型就是在偷读一条假信息（第 16 卡讲过：顺序不存在于数据里）。

The last card's accountant carries a worry: in the roster table, which hyperedge counts as "column 1" is pure bookkeeping — if re-registering changed the ledger, the model would be peeking at fake information (card 16: order does not exist in the data).

论文要证明的性质：把编组表的任意两列对调（"列交换"），式 (3) 算出的每个顶点的存档必须一个数都不动。下个步进器把这句证明拆成 4 步走完——你只管点"下一步"，不需要任何计算。

The property to prove: swapping any two columns of the roster table ("column exchange") must leave every vertex's Eq. (3) archive bit-for-bit unchanged. The stepper below walks that proof in 4 steps — just press "Next step"; no arithmetic needed.

例子EXAMPLE

例 1（证明步进器）：证明的全部家当只有两块地基——① "加法不挑顺序"（第 14 卡：3+1+2 与 2+3+1 同为 6）；② "ρ 是逐顶点的小函数"（第 25 卡：它每次只吃一个数）。把这两块接起来，性质就不用算也算出来了。

Example 1 (the proof stepper): the entire proof rests on two stones — (1) "addition ignores order" (card 14: 3+1+2 and 2+3+1 both give 6); (2) "ρ is a vertex-wise function" (card 25: it eats one number at a time). Join the stones and the property follows without any computation.

证明步进器 · 四步走完Proof stepper · four steps
每一步都只用到上面两块地基——跟着读即可。Every step draws only on the two stones above — read along.

第 1 步 · 规定"怎么换"。设 π 表示"把第 a 列和第 b 列对调"这个动作。换完之后的表记作 π(H)。注意：我们只换列的位置，不动任何 0/1 的值——像把两张卡片换一下抽屉。

Step 1 · define the swap. Let π denote "exchange columns a and b". The re-arranged table is written π(H). Note: only column positions move; no 0/1 value changes — two card-index cards swapped between drawers.

第 2 步 · 看某个顶点 v 的行和。沿 v 那一行把 0/1 加起来：原表里顺序是"第 1 列的值 + 第 2 列的值 + …"；换列后只是同样的几个数换了个相加顺序。地基①说：加法不挑顺序——和相等。

Step 2 · look at some vertex v's row sum. Add the 0/1s along v's row: the original order reads "column-1 value + column-2 value + …"; after swapping, the same numbers simply add in a different order. Stone (1): addition ignores order — equal sums.

第 3 步 · 对每一行都成立。第 2 步对 v 说的话，对 v1、v2、v3……每一行都同样成立（没有哪一行搞特殊）。所以：换列前后，所有顶点的"参加条数"逐一相等。论文的原文就一句：∑e∈E π(H)[v, π(e)] = ∑e∈E H[v, e]，说的正是这件事。

Step 3 · every row behaves the same. What step 2 said for v holds identically for v1, v2, v3 … (no row is special). Therefore: before and after the swap, every vertex's "membership count" matches one-for-one. The paper's line — ∑e∈E π(H)[v, π(e)] = ∑e∈E H[v, e] — says exactly this.

第 4 步 · 压一压，仍然一样。最后一步把和塞进 ρ。地基②说：ρ 是逐顶点的——它只看收到的那个数，对"这个数来自第几列"毫无概念。既然第 3 步保证了每个顶点收到的数一模一样，压出来的存档自然一模一样。证毕：列怎么换，Xs 一个字不变。

Step 4 · squash, still identical. Finally feed the sum into ρ. Stone (2): ρ is vertex-wise — it sees only the number received, with no idea "which column it came from". Step 3 guarantees each vertex receives the same number; the squashed archive is therefore identical too. QED: however columns swap, Xs does not budge.

例 2（数字验证 + 反例对照）：拿一张 3 顶点 2 列的编组表：v1 = [1,0]、v2 = [1,0]、v3 = [0,1]。行和 = 1、1、1。对调两列后：v1 = [0,1]、v2 = [0,1]、v3 = [1,0]，行和仍是 1、1、1 ✓——账本纹丝不动。再看一个"会翻车"的输出作对照：如果有人让模型输出"第 1 列的列和"，原表得 1+1+0 = 2，换列后得 0+0+1 = 1——2 ≠ 1，证明这种输出违反了不变性（对照第 15 卡的迁移题）。

Example 2 (numeric check + a counter-example): take a 3-vertex, 2-column roster: v1 = [1,0], v2 = [1,0], v3 = [0,1]. Row sums = 1, 1, 1. After swapping the two columns: v1 = [0,1], v2 = [0,1], v3 = [1,0], row sums still 1, 1, 1 ✓ — the ledger does not budge. Now a "crashes-and-burns" output for contrast: if a model output "the sum of column 1", the original gives 1+1+0 = 2 and the swapped gives 0+0+1 = 1 — 2 ≠ 1, so that output violates invariance (cf. card 15's transfer question).
